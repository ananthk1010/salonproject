# Evaluation

`golden.jsonl` is a starter set of 18 hand-authored, hand-labelled salon
messages, generated by `apps/api/scripts/generate_seed.py`. It is also the
demo's sample-message list (`GET /api/interactions`). `docs/PHASE1_PLAN.md`
section 7 calls for 120 messages for the real Phase 1 evaluation
(milestone M3) — this is a starting point, not that final set.

`fixtures/` holds one replay fixture per golden-set message, generated at
the same time from the same labels. This is what makes the public demo and
CI work with zero cost and no API key.

## Running the eval

```bash
# from the repo root, with apps/api's venv active (or its deps on PYTHONPATH)
python lab/jev_eval.py                    # replay mode, 1 run
python lab/jev_eval.py --mode live        # calls the real gateway; needs JEV_API_KEY
python lab/jev_eval.py --mode live --runs 3   # also computes the self-consistency flip rate
```

Writes `results.json` and `results.md`.

## Reading the results

**Replay mode numbers are circular.** The fixtures were built directly
from the golden-set labels, so accuracy in replay mode will always read
100% — that confirms the harness and the policy logic are wired correctly,
not that Jev is accurate. The real evaluation only means something in
`--mode live`, against the actual gateway. `jev_eval.py` prints this
caveat into `results.md` automatically whenever it runs in replay mode, so
it can't be mistaken for a genuine result later.

The policy regression check (does the confirmed/rejected outcome match the
exact branch-hours arithmetic) is deterministic code, not a model score —
it's expected to be 100% correct in both modes, since Jev is not involved
in that computation.
